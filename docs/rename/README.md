# План: переезд ebely → eberly и релиз 0.2.0

> Общая часть плана. Задачи — в `01-…`, `02-…`; каждую можно отдать
> в новый чат вместе с этим README. **Перед стартом прочитай
> [HANDOFF.md](HANDOFF.md), в конце — допиши туда** (правила ниже).

## Цель

Сейчас у проекта три имени: папка и репозиторий `evely`, npm-пакет
`ebely`. Сводим всё к одному — **eberly** — и выпускаем накопленные
в ветке `New-features` фичи (типы из схем, OpenAPI 3.0, JSDoc и `api/`,
`assert` на ошибки, `allowedHosts`, e2e, скиллы, английский README)
**одним релизом `eberly@0.2.0`**. `ebely@0.2.0` не выпускаем.

## Принятые решения (из обсуждения)

| Тема | Решение |
|------|---------|
| npm | Пакет в npm не переименовывается. Публикуем `eberly` (заглушка `0.0.1` уже наша), на `ebely` — `npm deprecate`. **Не** `unpublish` |
| Обратная совместимость | Нет. Чистое переименование: никаких алиасов `EbelyConfig`, команды `ebely` в CLI и т.п. (у `ebely` ~34 скачивания в месяц) |
| Версия | `eberly@0.2.0` — продолжение `ebely@0.1.1`; минорный бамп = ломающие изменения в 0.x. Получится сам из changesets (`minor` от 0.1.1) |
| Релиз фич | Только под новым именем, одним релизом. Ветка в `main` вливается **после** переименования (fast-forward: `main` — предок `New-features`) |
| README | Строка внизу: «Formerly published as `ebely`» |
| Домен / homepage | `homepage` пока на GitHub, сайта нет |
| GitHub | Репозиторий переименовывается в UI (`evely` → `eberly`), старые ссылки GitHub редиректит |

### 03. Папки (в самом конце, из обычного терминала, не из сессии Claude)

```bash
mv ~/code/lib/evely ~/code/lib/eberly
mv ~/.claude/projects/-Users-mac-code-lib-evely ~/.claude/projects/-Users-mac-code-lib-eberly
```

Вторая строка переносит историю сессий и память Claude Code: они лежат
по пути к папке, без неё `claude --resume` в новой папке их не увидит.
Затем открыть Claude Code уже в `~/code/lib/eberly`.

## HANDOFF.md — переписка между агентами

Задачи выполняют разные агенты в разных чатах. Всё, что агент понял
и что **меняет работу следующих задач**, он оставляет в
[HANDOFF.md](HANDOFF.md).

- **Перед стартом** — прочитать HANDOFF.md целиком.
- **В конце задачи** — дописать запись внизу (append-only, старое
  не править): что нашёл, что пошло не по плану, что следующему
  нужно знать/сделать. Не отчёт о сделанном — это видно в коммите.
- Если находка меняет шаги другой задачи — поправить и её файл,
  а в HANDOFF.md сослаться на правку.
- Пусто нечего сказать — так и написать одной строкой («без замечаний»),
  чтобы было видно, что задача закрыта.
