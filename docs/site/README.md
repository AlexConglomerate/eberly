# План: сайт eberly.dev — лендинг, документация, плейграунд

> Общая часть плана. Задачи — в `01-…` – `06-…`; каждую можно отдать
> в новый чат вместе с этим README. **Перед стартом прочитай
> [HANDOFF.md](HANDOFF.md), в конце — допиши туда** (правила ниже).

## Цель

Сайт, на котором разработчик за минуту понимает и **щупает** eberly:

1. лендинг: что это, пример «до и после», быстрый старт;
2. документация (то, что сейчас в README, разложенное по страницам);
3. плейграунд: слева OpenAPI-схема (правится или загружается своя),
   справа тест на сгенерированном клиенте — меняешь схему, тест краснеет
   там, где контракт поплыл;
4. настоящий запуск бэкенда и тестов — кнопкой «Open in StackBlitz».

Сайт можно поднять локально (`pnpm --filter @eberly-site/site dev` →
`http://localhost:4321`) и посмотреть до деплоя.

## Принятые решения (из обсуждения)

| Тема | Решение |
|------|---------|
| Где | Папка `site/` в этом репозитории, отдельный workspace-пакет `@eberly-site/site`, `private: true`. В npm не попадает (`files` в корневом `package.json` её не включает) |
| Стек | **Astro + Starlight** (лендинг — splash-страница Starlight, документация — её страницы). Плейграунд — **React-остров** (`@astrojs/react`) с **Monaco** (`@monaco-editor/react`) |
| Язык | Только английский |
| Документация | Полная — на сайте. README сокращается до витрины со ссылкой на сайт (задача 06) |
| Код в документации | Только из зелёных тестов: импорт файла `?raw` + вырезание региона `// #region docs:<имя>` … `// #endregion`. Руками код в `.mdx` не копировать |
| Генератор в браузере | Сайт импортирует `src/generator/*` напрямую (не через npm). Новый публичный API не нужен |
| Плейграунд v1 | Редактор схемы (YAML/JSON) + загрузка своей схемы (обрабатывается только в браузере, никуда не уходит). Перегенерация при уходе с поля. Справа редактируемый тест + read-only `generated.ts`. Кнопки-сценарии («переименовать поле» и т.п.) — **не** в v1 |
| Схема по умолчанию | Урезанная до постов схема Nest-примера, ~60 строк YAML |
| Фреймворки (Nest/oRPC) | Живой код бэкенда в браузере — нет. Настоящий запуск — StackBlitz |
| Хостинг и домен | Cloudflare Pages + домен `eberly.dev` у Cloudflare Registrar |
| Аналитика | **Umami Cloud** (бесплатный тариф): без cookie, есть время на сайте и собственные события. Cloudflare Web Analytics событий и времени визита не даёт. Содержимое и имя загруженной схемы в события **никогда** не попадают |
| YAML в библиотеке | Отдельная задача [`../NEXT-yaml-spec.md`](../NEXT-yaml-spec.md). Желательно сделать до 03 |

## HANDOFF.md — переписка между агентами

Задачи выполняют разные агенты в разных чатах. Всё, что агент понял
и что **меняет работу следующих задач**, он оставляет в
[HANDOFF.md](HANDOFF.md).

- **Перед стартом** — прочитать HANDOFF.md целиком.
- **В конце задачи** — дописать запись внизу (append-only, старое
  не править): что нашёл, что пошло не по плану, что следующему
  нужно знать/сделать. Не отчёт о сделанном — это видно в коммите.
- Если находка меняет шаги другой задачи — поправить и её файл,
  а в HANDOFF.md сослаться на правку.
- Нечего сказать — так и написать одной строкой («без замечаний»),
  чтобы было видно, что задача закрыта.

## Общий критерий «задача готова»

- `pnpm test`, `pnpm lint` зелёные; если задача трогала генератор или
  примеры — ещё и `pnpm e2e`;
- если задача трогала `site/` — `pnpm --filter @eberly-site/site build`
  проходит, а `dev` открывается локально;
- `CLAUDE.md` (структура, команды) и, если менялось устройство
  библиотеки, `ARCHITECTURE.md` обновлены;
- изменения библиотеки — с changeset;
- запись в HANDOFF.md.

Код — по правилам `CLAUDE.md` (в т.ч. options object для функций с
несколькими параметрами). Тексты на сайте и сообщения пользователю —
на английском.

## Вне скоупа

- Кнопки-сценарии в плейграунде (следующая итерация, после первой версии).
- Живой код Nest/oRPC в браузере, свой раннер тестов в браузере.
- Перевод сайта на другие языки.
- Блог, changelog-страница, поиск по сайту сверх встроенного в Starlight.
