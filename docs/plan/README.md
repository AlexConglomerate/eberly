# План: довести ebely до состояния «можно показывать»

> Общая часть плана. Каждая задача лежит в своём файле (`01-…` – `07-…`)
> и самодостаточна: её можно отдать в новый чат вместе с этим README.

## Цель

ebely — библиотека для e2e-тестов бэкенда через типизированный клиент,
сгенерированный из OpenAPI. Её нужно довести до уровня, когда:

1. генератор не падает на реальных свагерах (не только на oRPC);
2. агент пишет тесты, почти не тратя контекст: читает описания
   эндпоинтов, а не весь `generated.ts` и не код бэкенда;
3. негативные тесты (401/403/404) пишутся без `as any`;
4. тесты физически не могут уйти в прод;
5. одна команда проверяет, что всё работает на живых бэкендах;
6. скиллы `/ebely-setup` и `/ebely-write-tests` реально работают;
7. README на английском объясняет всё за 30 секунд (это идёт в резюме).

## Принятые решения (из обсуждения)

| Тема | Решение |
|------|---------|
| Версии OpenAPI | 3.1 — основная. 3.0 тоже генерируем (обрабатываем два отличия: `nullable` и `format: binary`). Swagger 2.0 — понятная ошибка, а не мусорный клиент |
| Тестовый бэкенд для «настоящего» свагера | Новый пример на **NestJS** (`examples/nest`), а не подкрутка oRPC |
| Типы | Схемы из `components/schemas` → именованные типы (`export type PostDto`). Это же чинит рекурсию |
| Группировка | По `tags`. Имена методов не трогаем (нейминг — отдельная задача потом) |
| Негативные тесты | Внутри `assert`: задекларированные статусы подсказываются и типизированы, любой 4xx/5xx можно без каста, незадекларированный 2xx/3xx — ошибка типов |
| Описания | summary + description эндпоинта — обязательно; описания полей и параметров — тоже (рендер централизован, это не костыль) |
| Файлы для агента | `ebely/api/INDEX.md` + `ebely/api/<группа>.<метод>.md`. Пишет их **код генератора**, не ИИ. Формат `.md` |
| Защита от прода | `allowedHosts`: localhost всегда можно, остальное только из списка. Проверка в общем `request`, только в режиме `test` |
| Параллельность | Тесты пока строго последовательные (`fileParallelism: false`) |
| E2E | Команда `pnpm e2e` в корне. CI — потом |
| Скиллы | Дописать оба; `npx ebely create` ставит их сам |
| README | Английский, примеры только из реально проходящих тестов |

## Как тестируем (чтобы тесты было легко поддерживать)

1. **Чистые функции — юнит-тестами на мини-спеках.** Спека собирается
   хелпером в 3–10 строк прямо в тесте. Один тест — одно поведение;
   название теста описывает поведение, а не реализацию.
2. **Проверяем значимые фрагменты, а не снапшот всего файла.** Тест
   рендера ищет `export type PostDto =` или `: WorldApi`, а не сравнивает
   сотни строк. Тогда правка соседнего куска рендера не роняет десятки
   тестов.
3. **Поведение типов — файлами с `@ts-expect-error`**, которые проверяет
   обычный `tsc` (`pnpm lint`). Без новых зависимостей. Если ожидаемая
   ошибка типов пропадёт, `tsc` сам скажет «unused @ts-expect-error».
4. **Каждый баг-фикс начинается с падающего теста** (например, мини-спека
   с рекурсией, которая сейчас даёт `Maximum call stack size exceeded`).
5. **Интеграция — `pnpm e2e`** на живых бэкендах из `examples/`,
   включая `tsc --noEmit` по тестам (vitest типы не проверяет).
6. **`pnpm test` запускает тесты по glob** (`src/**/*.test.ts`), чтобы
   новый тест-файл подхватывался сам, без правки списка в `package.json`.

## Общий критерий «задача готова»

- `pnpm test` и `pnpm lint` зелёные (после 05 — ещё и `pnpm e2e`);
- новые файлы и поведение отражены в `CLAUDE.md` (структура) и
  `ARCHITECTURE.md` (как устроено);
- добавлен changeset. Изменения ломающие → весь набор выйдет как **0.2.0**
  одним релизом после 07.

## Вне скоупа (сознательно отложено)

- Поддержка Swagger 2.0 (только понятная ошибка).
- Эвристики имён методов (`PostsController_create`, `read_items_items_get`).
- Синтезированные имена для инлайн-схем (`PostsCreateBody`) — у oRPC схемы
  остаются инлайновыми.
- Корпус чужих свагеров (GitHub, Stripe) и бэкенды на Python/Go/Rust —
  в конце, когда ядро отполировано.
- CI (GitHub Actions); проверка детерминизма генерации через `git diff`.
- Лендинг (после README), замер экономии токенов.
- Параллельные тесты.
- Рецепт «поднимать бэкенд из тестов» через vitest `globalSetup`.
- CLI «вызвать эндпоинт и посмотреть ответ», валидация ответа по схеме,
  MCP-сервер.
- Контекст запроса (метод + путь) в тексте ошибки `assert`.
- Перевод комментариев в коде и в `generated.ts` на английский.
- Название: репозиторий `evely`, пакет `ebely` — решить до того, как
  ссылка попадёт в резюме.
