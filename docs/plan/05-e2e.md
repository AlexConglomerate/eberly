# 05 — E2E: тест-проект для Nest, `pnpm e2e`, typecheck, последовательные тесты, шаблон

> Самодостаточная задача. Общие решения, порядок и принципы тестов — в
> [README.md](README.md). Зависит от 01–04.

## Цель

Одна команда из корня — `pnpm e2e` — честно проверяет, что всё работает
на живых бэкендах. Она собирает библиотеку и для каждого примера проходит
путь «свагер → клиент → `tsc` → vitest». Пока это локальная команда;
CI потом просто её вызовет.

## Проверенные факты

- Примеры импортируют `ebely` из workspace, а `exports` в `package.json`
  указывают на `dist/`. Поэтому **сначала нужен `pnpm build`**, иначе
  примеры тестируют старую сборку.
- Все `your-app` слушают `:3000` (`process.env.PORT ?? 3000`), поэтому
  примеры гоняем **по очереди**.
- **Vitest не проверяет типы** (esbuild их просто вырезает). Поломку
  контракта (бэкенд переименовал поле) `vitest run` не поймает. Нужен
  `tsc --noEmit` по тест-проекту.
- **Vitest по умолчанию запускает тест-файлы параллельно.** В
  `simple-auth` четыре файла, и каждый вызывает `world.clearDatabase()`:
  флаки уже заложены. Нужен `fileParallelism: false`.
- Баг в `examples/simple/test-with-ebely/tests/test1.test.ts`:
  `user1.fullRegister` вызывается дважды (для `a@x.com` и `b@x.com`), а
  `user2` так и не регистрируется.
- `clone/tests` — это шаблон, который `npx ebely create` копирует
  пользователю. Он сделан ручной копией `examples/simple/test-with-ebely`
  и уже разошёлся с ней: в `ebely.ts` и `hooks.ts` нет комментариев,
  нет теста на коллизию имён. Любая правка примера в него сама не попадёт.
- `examples/simple/test-with-ebely/tests/draw.ts` — закомментированный
  эскиз API. В шаблон его не берём.

## A. Тест-проект `examples/nest/test-with-ebely`

Структура как у остальных примеров, пакет `@ebely-examples/nest-test-with-ebely`.

- `ebely/ebely.ts`: `url: 'http://localhost:3000'`, swagger из файла,
  `userStore`, `worldStore`, `hooks`.
- `userStore.ts`:
  - переменные `email`, `password`, `accessToken`, `lastPostId`;
  - сценарий `signUp({ email, password })`: register (201) → login (200) →
    сохранить токен.
- `worldStore.ts`: `reset()` → `test.reset`.
- `hooks.ts`:
  - `globalBefore` подставляет Bearer;
  - `posts.create.after` сохраняет `lastPostId` при 201.
- Тесты. В каждом файле `beforeAll(() => world.reset())`, email-ы
  уникальные через `randomUUID()`.

  | Файл | Что проверяет |
  |------|---------------|
  | `auth.test.ts` | register → 201 (тело типизировано); повтор → 409 с типизированным `ErrorDto`; кривой email → 400 (`message` — массив); неверный пароль → 401; `me` без токена → 401, с токеном → 200; устаревший `whoami` работает |
  | `posts.test.ts` | **два пользователя:** Алиса создаёт (201); Боб удаляет → 403; Алиса публикует → `publishedAt` был `null`, стал строкой; Алиса удаляет → 204; `get` → 404 |
  | `comments.test.ts` | дерево ответов; deep-partial `assert` по рекурсивной структуре: `[{ text: 'a', replies: [{ text: 'b' }] }]` |
  | `avatar.test.ts` | загрузка `tests/fixtures/avatar.png` по пути → `avatarUrl` заполнен |
  | `tests/types.ts` | не запускается vitest, проверяется `typecheck`: `@ts-expect-error` на `user.posts.create(...).assert(200)` (там 201) и на лишнее поле в теле. Страхует требование «видно 200 или 201» на настоящем клиенте |

- `swagger.json` — копия из `your-app`, её обновляет `pnpm e2e`.

## B. Во всех тест-проектах (simple, simple-auth, nest и шаблон)

- `vitest.config.ts` с `fileParallelism: false` и комментарием, почему
  (общая БД, `reset` в `beforeAll`).
- Скрипт `"typecheck": "tsc --noEmit"`.
- Исправить баг с `user2` в `test1.test.ts`.

## C. Команда `pnpm e2e`

Корневой `package.json`: `"e2e": "tsx scripts/e2e.ts"`.

`scripts/e2e.ts`, без зависимостей (`node:child_process`):

1. `pnpm build`.
2. `tsx scripts/sync-template.ts` (см. D).
3. Проверить, что порт 3000 свободен. Если занят — выйти с сообщением
   «stop your dev server on :3000».
4. Для каждого примера по очереди: `simple`, `simple-auth`, `nest`:
   1. в `your-app` выполнить `swagger` и скопировать
      `your-app/swagger/swagger.json` → `test-with-ebely/swagger.json`;
   2. запустить `your-app start` с `PORT=3000` и `TEST_MODE=1` отдельной
      группой процессов;
   3. ждать готовности: опрашивать `http://localhost:3000/` до любого
      HTTP-ответа, таймаут 60 с (Nest сначала собирается). По таймауту
      показать лог бэкенда;
   4. в `test-with-ebely` выполнить `client:generate` → `typecheck` → `test`;
   5. в `finally` убить группу процессов бэкенда. То же на `SIGINT` и
      `SIGTERM`, чтобы `Ctrl+C` не оставлял висящий сервер.
5. Смоук шаблона: `node bin/ebely.mjs create <tmp>`. Проверить, что на
   месте `ebely/ebely.ts`, `vitest.config.ts`, `.claude/skills/ebely-setup`
   (после 06), а в `package.json` стоит `ebely: ^<версия>`.
6. Итог: таблица ✓/✗ по примерам с шагом, на котором упало. Код выхода 1
   при любом провале.

Флаг `--only <пример>` — прогнать один пример при разработке.

Скрипт собирается из маленьких функций: `run({ cmd, cwd, env })`,
`startBackend`, `waitForHttp`, `stopBackend`, `runExample`. Вывод дочерних
процессов идёт с префиксом `[nest]`, `[simple]` и т. п.

`pnpm e2e` перегенерирует `swagger.json`, `generated.ts` и `ebely/api/`.
Если они изменились — это ожидаемо, коммитим. Проверка детерминизма через
`git diff --exit-code` — потом, вместе с CI.

## D. Шаблон собирается из примера

- `scripts/sync-template.ts` копирует `examples/simple/test-with-ebely` →
  `clone/tests`, кроме `node_modules` и `tests/draw.ts`. Папку
  предварительно очищает.
- Запуск: в `prepublishOnly` (`pnpm run build && tsx scripts/sync-template.ts`)
  и в начале `pnpm e2e`.
- `clone/` добавить в `.gitignore`. Шаблон больше не правится руками,
  поэтому расходиться нечему.
- В `files` из `package.json` три glob-а (`clone/tests/ebely`,
  `clone/tests/tests`, `clone/tests/*.json`) заменить на `"clone/tests"`.
  Иначе новый `vitest.config.ts` в пакет не попадёт.
- `bin/ebely.mjs create` и так пишет свой standalone `tsconfig.json` с
  `include: ["ebely", "tests"]`. Проверить, что `typecheck` в созданном
  проекте работает.

## Готово когда

- `pnpm e2e` зелёный на всех трёх примерах, смоук шаблона проходит;
- **проверка поломки контракта (один раз руками):** переименовать поле в
  `PostDto` Nest-бэкенда → `pnpm e2e --only nest` падает на шаге
  `typecheck` → откатить;
- `Ctrl+C` посреди прогона не оставляет процесс на `:3000`.
