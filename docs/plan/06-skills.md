# 06 — Скиллы `ebely-setup` и `ebely-write-tests` + простая установка

> Самодостаточная задача. Общие решения, порядок и принципы тестов — в
> [README.md](README.md). Зависит от 03 (`ebely/api/`), 04 и 05 (команды
> `typecheck`, шаблон).

## Как сейчас

`skills/ebely-setup/SKILL.md` и `skills/ebely-write-tests/SKILL.md` —
заглушки (`> ЗАГЛУШКА`, список TODO), хотя README их уже рекламирует.
Устанавливаются отдельной командой `npx ebely skills`.

## Цель

1. `npx ebely create my-tests` → открыть Claude Code в `my-tests` →
   `/ebely-setup` → пара вопросов → зелёные смоук-тесты.
2. Дальше `/ebely-write-tests <сценарий словами>` → тест написан и
   прогнан, а агент не читал ни `generated.ts`, ни код бэкенда.

## Установка

- `npx ebely create` **сам** кладёт скиллы в `<dir>/.claude/skills/`.
  Отдельный шаг не нужен.
- `npx ebely skills` остаётся для существующих проектов и для обновления.
  Скиллы копируются, поэтому после обновления `ebely` команду нужно
  запустить ещё раз. Это пойдёт в README.
- Скиллы пишем **на английском**: пакет публичный.
- Каждый скилл короче ~150 строк. Он сам попадает в контекст, так что
  экономия токенов начинается с него.

## `ebely-setup`

**Спросить у пользователя** (из свагера это не вывести):

1. Где свагер: URL поднятого бэкенда (`/swagger.json`, `/openapi.json`,
   у Nest — `/docs-json`) или файл.
2. URL бэкенда (по умолчанию `http://localhost:3000`). Если это не
   localhost — явно уточнить, что это **не прод**, и добавить хост в
   `allowedHosts`.
3. Авторизация: какие эндпоинты регистрируют и логинят, где в ответе
   токен, в каком заголовке его слать.
4. Тестовый режим: есть ли эндпоинт сброса данных, как получить код из
   письма или SMS. Если чего-то нет — сказать, что добавить в бэкенд,
   и продолжить с тем, что есть.

**Шаги:**

1. Если это ещё не ebely-проект — `npx ebely create <dir>` (рекомендовать
   отдельную папку или репозиторий).
2. `ebely/ebely.ts`: `url`, источник свагера, `allowedHosts` при
   необходимости.
3. `pnpm install`, `pnpm run client:generate`.
4. Прочитать `ebely/api/INDEX.md`. **Не** читать `generated.ts` целиком.
5. `userStore.ts`: переменные и сценарий `signUp`/`signIn`, который
   сохраняет токен. `hooks.ts`: `globalBefore` с Bearer, after-хуки,
   которые сохраняют id созданных сущностей. `worldStore.ts`: `reset()`,
   если у бэкенда есть сброс.
6. Смоук-тесты: на каждую группу один happy path и один негативный
   (401/404).
7. `pnpm typecheck && pnpm test`, чинить до зелёного.
8. Отчёт: что покрыто и чего бэкенду не хватает для тестирования.

**Правила:**

- не редактировать `generated.ts` и `ebely/api/`;
- тесты последовательные;
- данные уникальные на каждый тест (`randomUUID()`);
- никогда не направлять тесты на прод.

## `ebely-write-tests`

**Шаги:**

1. Если свагер менялся — сначала `pnpm run client:generate`.
2. `ebely/api/INDEX.md` → выбрать эндпоинты под сценарий.
3. Открыть **только** их `<группа>.<метод>.md`.
4. Посмотреть `userStore.ts`, `worldStore.ts`, `hooks.ts`: какие сценарии
   и переменные уже есть.
5. Написать тест:
   - каждый человек в сценарии — свой `world.createUser()`;
   - переиспользовать сценарии стора;
   - `assert(status, частичное тело)`: статусы брать из md, 4xx/5xx можно
     любые;
   - id брать из переменных стора, которые сохраняют хуки.
6. Если многошаговая подготовка повторяется — вынести её в сценарий
   `userStore`. Если нужно запоминать id — добавить after-хук.
7. `pnpm typecheck && pnpm test`.

**Шпаргалка API** внутри скилла (~30 строк, чтобы не читать
`ARCHITECTURE.md`):

- `World`, `createUser`;
- `assert`: статусы, deep-partial, `as const` для переменной;
- `get`/`set` стора;
- `globalBefore` / `after` / `globalRetry` с примерами;
- загрузка файла по пути.

## Проверка (руками)

Пакет ещё не опубликован, поэтому так:

1. `pnpm pack` в корне → `ebely-<версия>.tgz`.
2. `node bin/ebely.mjs create /tmp/try-ebely`, а в его `package.json`
   поставить `"ebely": "file:<путь к tgz>"`.
3. Поднять Nest-бэкенд с `TEST_MODE=1`.
4. В `/tmp/try-ebely` открыть Claude Code → `/ebely-setup` → тесты
   зелёные.
5. `/ebely-write-tests "Bob cannot delete Alice's post"` → тест написан и
   зелёный. По транскрипту убедиться, что `generated.ts` и код бэкенда не
   открывались.
