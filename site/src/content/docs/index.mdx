eberly reads your backend's OpenAPI spec (JSON or YAML) and generates a typed TypeScript
client for tests. Every test user gets their own state, hooks keep tokens and
ids for you, and when the backend changes its contract, the tests stop
compiling.

One `assert` checks the status and the body: exact values, schemas (Zod,
Valibot, ArkType) and vitest matchers, all typed by the spec.

## Built for AI agents

An agent needs two things to write tests: the URL of a running backend and its
OpenAPI spec. No access to the backend code.

- **Reads only what the test needs.** `eberly/api/INDEX.md` lists the
  endpoints. The agent opens one short file per endpoint it calls, not the
  whole spec or the generated client.
- **TypeScript is the feedback loop.** A wrong field or status doesn't
  compile, and the error points at that exact field. The agent fixes it
  without guessing.
- **Skills included.** `npx eberly create` installs Claude Code skills for
  setup and test writing.

What keeps a human's head clear keeps an agent's context small. More in
[Writing tests with AI agents](/guides/ai-agents/) and
[Motivation](/motivation/).

## Why eberly

<CardGrid>
  <Card title="Typed client from your swagger" icon="seti:typescript">
    Request bodies, path params, response bodies and statuses come from the
    spec. The backend renames a field, and the test turns red before it even
    runs.
  </Card>
  <Card title="Many users, each with their own state" icon="star">
    `world.createUser()` gives a user with their own token and variables, so
    "Bob can't touch Alice's post" is three lines.
  </Card>
  <Card title="Hooks keep tokens and ids for you" icon="puzzle">
    A `before` hook adds the token, an `after` hook saves the id of the created
    entity. Tests don't pass them around.
  </Card>
  <Card title="Status with autocomplete, partial body check" icon="approve-check">
    `res.assert(201, { title })` suggests the statuses declared in the spec,
    checks only the fields you pass (at any depth) and narrows `res.body` to
    the type of that status.
  </Card>
  <Card title="Transparent token refresh" icon="random">
    A `globalRetry` hook refreshes the token on `401`, and eberly replays the
    request: the test sees `200`.
  </Card>
  <Card title="File upload by path" icon="document">
    `{ body: { file: './avatar.png' } }`, and eberly builds the multipart form.
  </Card>
</CardGrid>
