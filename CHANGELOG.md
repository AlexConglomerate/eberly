## 0.2.0

### Minor Changes

- 87ebcbf: E2E на живых бэкендах и шаблон из примера.

  - `res.assert(status)` сужает `.body` до тела задекларированного статуса:
    `res.assert(201).body.id` без каста, даже если у эндпоинта есть
    задекларированные ошибки (раньше `body` был союзом `PostDto | ErrorDto`).
  - Шаблон `npx eberly create` собирается из `examples/simple/test-with-eberly`
    при публикации: в него попали `vitest.config.ts`
    (`fileParallelism: false` — тест-файлы идут по очереди, база общая),
    скрипт `typecheck` (`tsc --noEmit`) и исправленный пример теста
    (второй пользователь теперь регистрируется).

- b3d3924: Описания эндпоинтов: JSDoc в клиенте и папка `api/` для агента.

  - JSDoc из свагера: у метода в `WorldApi` — summary, description, маршрут
    (`` `POST /posts` ``) и `@deprecated`; у path/query-параметров и полей
    схем — их description (у полей ещё `@deprecated`). `*/` в описаниях
    экранируется.
  - `client:generate` теперь пишет рядом с клиентом папку `api/`:
    `INDEX.md` (строка на эндпоинт) и `<группа>.<метод>.md` с описанием,
    готовым вызовом, входом, ответами и типами. Агент читает их вместо
    всего `generated.ts`. Перед записью удаляются только файлы с маркером
    `AUTO-GENERATED by eberly` — чужие файлы в папке не трогаются.
    Рекомендуется коммитить эту папку.
  - `generateClient` возвращает ещё `docsDir`.

- b475484: README на английском: «до и после», быстрый старт, примеры из тестов
  `pnpm e2e`, требования к бэкенду, подводные камни, справка по конфигу и API.

  - `Readme.md` → `README.md`, добавлен `LICENSE` (MIT).
  - `package.json`: `description`, `keywords`, `repository`, `homepage`,
    `bugs` для страницы на npm.
  - `npx eberly create` в подсказке «вручную» теперь зовёт
    `pnpm typecheck && pnpm test` и даёт ссылку на README.

- 1bcad63: Генератор: версии OpenAPI, именованные типы, группы по тегам.

  - OpenAPI 3.0 поддерживается наравне с 3.1: `nullable: true` → `| null`,
    `format: binary` → `FileInput`. Swagger 2.0 и неизвестные версии дают
    понятную ошибку вместо мусорного клиента.
  - Схемы из `components/schemas` рендерятся именованными типами
    (`export type PostDto = …`), `$ref` — именем. Рекурсивные схемы больше
    не роняют генератор (`Maximum call stack size exceeded`). Типы можно
    импортировать: `import type { PostDto } from './generated'`.
  - Типы вызовов описаны один раз — в `WorldApi` (там же JSDoc `summary`);
    `buildApiTree` возвращает `WorldApi`, `generated.ts` стал заметно короче.
  - **Ломающее:** группа методов теперь берётся из первого тега
    (`User Management` → `userManagement`), а не из префикса `operationId`.
    Фолбэки: префикс `operationId` → первый сегмент пути → `default`.
    Если теги не совпадают с префиксом `operationId`, имена групп
    поменяются. Группы `get`/`set`/`api`/`store`/… получают суффикс `Api`.

- df69eff: Пакет переименован: `ebely` → `eberly`. Старый `ebely` больше не
  обновляется. Обратной совместимости нет — алиасов старых имён нет.

  Миграция:

  - `npm uninstall ebely && npm i -D eberly`.
  - Импорты `from 'ebely'` → `from 'eberly'`; типы и классы
    `Ebely*` → `Eberly*` (`EberlyConfig`, `EberlyUnsafeHostError`,
    `EberlyAssertionError`, `EberlyHookTree`, `generateEberlyClient`).
  - Папка `ebely/` → `eberly/`, конфиг `ebely/ebely.ts` → `eberly/eberly.ts`
    (и пути в `tsconfig.json` / `configImport`, если указаны явно).
  - **Удалить старую `ebely/api/`** (или `eberly/api/` после переименования
    папки) перед `client:generate`: старые файлы несут прежний маркер
    `AUTO-GENERATED by ebely`, генератор их не узнает и не удалит.
  - CLI: `npx ebely …` → `npx eberly …`. Переустановить скиллы:
    `npx eberly skills` (теперь `/eberly-setup` и `/eberly-write-tests`),
    старые `.claude/skills/ebely-*` удалить.

- fc56f0c: Рантайм: `assert` на ошибочные статусы, `allowedHosts`, английские сообщения.

  - `res.assert(...)`: любой 4xx/5xx, которого нет в свагере, передаётся
    без каста (`assert(403)` вместо `assert(403 as any)`). Задекларированные
    статусы по-прежнему подсказываются, их тело типизировано — в том числе
    у 4xx. Незадекларированный 1xx–3xx — ошибка типов. Статус из переменной
    типа `number` требует `as const`.
  - Новое поле конфига `allowedHosts?: string[]` (точный hostname или
    `*.domain`). В режиме `test` клиент ходит только на loopback и хосты из
    списка, иначе `new World()` / `createUser()` бросают
    `EberlyUnsafeHostError` до первого запроса. **Ломающее:** тесты против
    не-localhost бэкенда теперь требуют `allowedHosts`. Клиент нужно
    перегенерировать. Экспорт: `assertHostAllowed`, `EberlyUnsafeHostError`,
    тип `UndeclaredErrorStatus`.
  - Сообщения для пользователя на английском: ошибки `assert`, `loadSpec`,
    вывод CLI `eberly`.

- d51c1da: Скиллы `/eberly-setup` и `/eberly-write-tests` для Claude Code.

  - Оба скилла дописаны (были заглушками): вопросы пользователю, шаги,
    правила и шпаргалка по API. Агент читает `eberly/api/`, а не
    `generated.ts` и не код бэкенда.
  - `npx eberly create` сам кладёт скиллы в `<dir>/.claude/skills/`.
    `npx eberly skills` остаётся для существующих проектов и обновления
    (скиллы копируются — после апдейта `eberly` запустить ещё раз).

## 0.1.0

### Minor Changes

- 8771925: Загрузка файлов через сгенерированный клиент (multipart/form-data).

  Файловые поля (OpenAPI 3.1: `{ type: 'string', contentMediaType }`)
  типизируются как `FileInput` (путь-строка / `URL` / `{ path }` /
  `{ content }` / `Blob`/`File`), а общий `request` сам собирает `FormData`
  и читает пути с диска. Кодировка имён полей для МАССИВА файлов настраивается
  один раз через `EbelyConfig.files.encoding`:
  `'repeat'` (дефолт, busboy/Go/Rust), `'bracket-index'` (oRPC/PHP/Rails),
  `'bracket-empty'` или своя функция. Новые публичные экспорты:
  `toMultipartFormData`, `toBlob`, `mimeFromName`, типы `FileInput`,
  `FileEncoding`, `FileFieldMeta`. См. `ARCHITECTURE.md §9`.
